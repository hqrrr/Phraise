## Transport

Harper LSP communicates via **JSON-RPC 2.0** over **stdin/stdout** (with `--stdio` flag) or **TCP** (default: `127.0.0.1:4000`).

### Framing

LSP uses HTTP-style headers with `Content-Length`:

```
Content-Length: <N>\r\n\r\n
{json body of exactly N bytes}
```

Example (initialize request):

```
Content-Length: 114\r\n\r\n{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"processId":null,"rootUri":null,"capabilities":{},"trace":"off"}}
```

## LSP Message Flow

```
Client                              Server
  |                                    |
  |--- initialize (request id=1) ----->|
  |<--- initialize result (id=1) ------|
  |--- initialized (notification) ---->|
  |<--- window/logMessage -------------|  (optional)
  |<--- workspace/configuration ------ |  (server request, must respond)
  |--- [response] workspace/config -->|
  |--- textDocument/didOpen ---------->|
  |<--- workspace/configuration -------|  (server request, must respond)
  |--- [response] workspace/config -->|
  |<--- client/registerCapability -----|  (server request, must respond)
  |--- [response] regCapability ----->|
  |<--- textDocument/publishDiagnostics|  (async, 0.5-3s after didOpen)
  |--- textDocument/codeAction (id=N)->|
  |<--- textDocument/codeAction (id=N)-|  (rich suggestions returned)
  |--- shutdown (request id=M) ------->|
  |<--- publishDiagnostics (empty) ----|  (clears diagnostics)
  |<--- shutdown result (id=M) --------|
  |--- exit (notification) ----------->|
  |                              [exit 0]|
```

### Important: Server-Initiated Requests

After `initialized`, harper-ls sends **server-to-client requests** that the client MUST respond to:

1. `workspace/configuration` — Server asks for user settings. Respond with `[]` (or actual config).
2. `client/registerCapability` — Server wants to register for `workspace/didChangeWatchedFiles`. Respond with `null`.

If these are not answered, the server may not send diagnostics or may behave incorrectly.

## Message Formats (Exact Capture)

### 1. `initialize` (Client → Server Request)

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "method": "initialize",
  "params": {
    "processId": null,
    "rootUri": null,
    "capabilities": {},
    "trace": "off"
  }
}
```

### 2. `initialize` (Server → Client Response)

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": {
    "capabilities": {
      "codeActionProvider": true,
      "executeCommandProvider": {
        "commands": [
          "HarperRecordLint",
          "HarperAddToUserDict",
          "HarperAddToWSDict",
          "HarperAddToFileDict",
          "HarperOpen",
          "HarperIgnoreLint"
        ]
      },
      "textDocumentSync": {
        "change": 1,
        "openClose": true,
        "save": true
      }
    },
    "serverInfo": {
      "name": "harper-ls",
      "version": "2.4.0"
    }
  }
}
```

**Key capabilities:**
- `textDocumentSync.change: 1` = **Full** (server wants whole document on each change, not incremental diffs)
- `textDocumentSync.openClose: true` — server expects `didOpen`/`didClose`
- `textDocumentSync.save: true` — server wants `didSave` notifications
- `codeActionProvider: true` — supports `textDocument/codeAction`
- `executeCommandProvider` — 6 Harper-specific commands for dict management and lint control

### 3. `initialized` (Client → Server Notification)

```json
{
  "jsonrpc": "2.0",
  "method": "initialized",
  "params": {}
}
```

### 4. `window/logMessage` (Server → Client Notification)

Sent after `initialized` to confirm server startup:

```json
{
  "jsonrpc": "2.0",
  "method": "window/logMessage",
  "params": {
    "message": "Server initialized!",
    "type": 3
  }
}
```

`type: 3` = MessageType.Info (per LSP spec).

### 5. `workspace/configuration` (Server → Client Request)

Harper asks for configuration settings. The client MUST respond:

```json
{
  "jsonrpc": "2.0",
  "method": "workspace/configuration",
  "params": {
    "items": [{}]
  },
  "id": 0
}
```

**Client response:**

```json
{
  "jsonrpc": "2.0",
  "id": 0,
  "result": []
}
```

Note: The server sends this multiple times. The `items` array can be extended with specific configuration keys, but in our test it was always `[{}]`.

### 6. `client/registerCapability` (Server → Client Request)

Harper registers for file-watching. The client MUST respond:

```json
{
  "jsonrpc": "2.0",
  "method": "client/registerCapability",
  "params": {
    "registrations": [
      {
        "id": "workspace/didChangeWatchedFiles",
        "method": "workspace/didChangeWatchedFiles",
        "registerOptions": {
          "watchers": [
            {
              "globPattern": "**/*",
              "kind": 4
            }
          ]
        }
      }
    ]
  },
  "id": 1
}
```

**Client response:**

```json
{
  "jsonrpc": "2.0",
  "id": 1,
  "result": null
}
```

`kind: 4` = WatchKind.All (create + change + delete).

### 7. `textDocument/didOpen` (Client → Server Notification)

```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/didOpen",
  "params": {
    "textDocument": {
      "uri": "file:///test.txt",
      "languageId": "plaintext",
      "version": 1,
      "text": "helo wrld is a tset"
    }
  }
}
```

### 8. `textDocument/publishDiagnostics` (Server → Client Notification)

Sent asynchronously after `didOpen`. Includes all spelling/grammar issues:

```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/publishDiagnostics",
  "params": {
    "uri": "file:///test.txt",
    "diagnostics": [
      {
        "code": "SpellCheck",
        "range": {
          "start": { "line": 0, "character": 0 },
          "end": { "line": 0, "character": 4 }
        },
        "severity": 4,
        "source": "Harper",
        "message": "Did you mean to spell `helo` this way?"
      }
    ]
  }
}
```

**Diagnostic fields:**
- `code`: `"SpellCheck"` for spelling errors (may also have grammar codes)
- `severity`: `4` = **Hint** (per LSP spec: 1=Error, 2=Warning, 3=Info, 4=Hint)
- `source`: `"Harper"`
- `message`: Human-readable suggestion

On `shutdown`, harper-ls clears diagnostics by sending `publishDiagnostics` with an empty array:
```json
{
  "jsonrpc": "2.0",
  "method": "textDocument/publishDiagnostics",
  "params": {
    "uri": "file:///test.txt",
    "diagnostics": []
  }
}
```

### 9. `textDocument/codeAction` (Client → Server Request → Response)

**Request:**

```json
{
  "jsonrpc": "2.0",
  "id": 100,
  "method": "textDocument/codeAction",
  "params": {
    "textDocument": { "uri": "file:///test.txt" },
    "range": {
      "start": { "line": 0, "character": 0 },
      "end": { "line": 0, "character": 4 }
    },
    "context": {
      "diagnostics": [
        {
          "code": "SpellCheck",
          "range": {
            "start": { "line": 0, "character": 0 },
            "end": { "line": 0, "character": 4 }
          },
          "severity": 4,
          "source": "Harper",
          "message": "Did you mean to spell `helo` this way?"
        }
      ]
    }
  }
}
```

**Response (rich — NOT empty):**

Each diagnostic returns 7 code actions:

```json
{
  "jsonrpc": "2.0",
  "id": 100,
  "result": [
    {
      "title": "Replace with: \"hello\"",
      "kind": "quickfix",
      "edit": {
        "changes": {
          "file:///test.txt": [
            {
              "newText": "hello",
              "range": {
                "start": { "line": 0, "character": 0 },
                "end": { "line": 0, "character": 4 }
              }
            }
          ]
        }
      },
      "command": {
        "title": "Record lint statistic",
        "command": "HarperRecordLint",
        "arguments": [
          "{\"Lint\":{\"kind\":\"Spelling\",\"context\":[{\"content\":\"helo\",\"kind\":{\"kind\":\"Word\",\"value\":null}}]}}"
        ]
      }
    },
    { "title": "Replace with: \"halo\"", "kind": "quickfix", "edit": { ... } },
    { "title": "Replace with: \"held\"", "kind": "quickfix", "edit": { ... } },
    {
      "title": "Ignore Harper error.",
      "command": "HarperIgnoreLint",
      "arguments": [ "file:///test.txt", { "lint_kind": "Spelling", ... } ]
    },
    {
      "title": "Add \"helo\" to the user dictionary.",
      "command": "HarperAddToUserDict",
      "arguments": [ "helo", "file:///test.txt" ]
    },
    {
      "title": "Add \"helo\" to the workspace dictionary.",
      "command": "HarperAddToWSDict",
      "arguments": [ "helo", "file:///test.txt" ]
    },
    {
      "title": "Add \"helo\" to the file dictionary.",
      "command": "HarperAddToFileDict",
      "arguments": [ "helo", "file:///test.txt" ]
    }
  ]
}
```

**Code action types returned:**
1. **Spelling replacement suggestions** (kind: `quickfix`) — 1–3 replacements per diagnostic, each with an `edit` containing `changes` with the replacement `newText` and `range`
2. **Ignore error** (command: `HarperIgnoreLint`) — suppresses the diagnostic
3. **Add to user dictionary** (command: `HarperAddToUserDict`)
4. **Add to workspace dictionary** (command: `HarperAddToWSDict`)
5. **Add to file dictionary** (command: `HarperAddToFileDict`)

Each quickfix also includes a `HarperRecordLint` command for telemetry.

### 10. `shutdown` (Client → Server Request → Response)

**Request** — NOTE: Do NOT include `"params": {}` (harper-ls returns error `-32602`).

```json
{
  "jsonrpc": "2.0",
  "id": 999,
  "method": "shutdown"
}
```

**Response:**

```json
{
  "jsonrpc": "2.0",
  "id": 999,
  "result": null
}
```

### 11. `exit` (Client → Server Notification)

```json
{
  "jsonrpc": "2.0",
  "method": "exit"
}
```

Server exits with code 0.

## Key Observations

### 1. `publishDiagnostics` Timing

`publishDiagnostics` is sent **asynchronously** after `didOpen`. In our test, diagnostics arrived **~0.5–1.5 seconds** after `didOpen`. The server processes the text in a background task and pushes results when ready.

### 2. Server-Initiated Requests

Harper-ls sends several **requests** (not notifications) that the client must respond to:
- `workspace/configuration` — at least 2 times during initialization
- `client/registerCapability` — once, to register file watchers

If not answered, diagnostics do not arrive (the server waits for configuration).

### 3. Code Actions Work Correctly

Contrary to earlier assumptions, `textDocument/codeAction` **does return results**. For each spelling diagnostic, Harper returns:
- 1–3 spelling replacement suggestions as `quickfix` items
- 3 dictionary management commands
- 1 ignore-lint command

### 4. Shutdown Clears Diagnostics

When `shutdown` is sent, Harper first sends an empty `publishDiagnostics` to clear all markers, then responds with `{ "result": null }`.

### 5. Single-File Binary

`harper-ls.exe` is a self-contained ~55 MB Rust binary with no external DLL dependencies.

### 6. Memory Usage

The Rust binary is large (~55 MB on disk) compared to JS-based LSP servers, but typical for compiled Rust binaries that bundle their runtime.

## Frequently Asked Questions

**Q: Is `publishDiagnostics` synchronous or asynchronous?**
A: **Asynchronous.** It arrives 500–1500ms after `didOpen`, not as a direct response. The client needs to listen for server→client notifications continuously.

**Q: What's the typical latency?**
A: ~500–1500ms for a short sentence. Larger documents may take longer.

**Q: Does harper-ls send diagnostics on `didChange` too?**
A: Not tested in this spike. The `textDocumentSync: { change: 1 }` capability means the server wants the full document text on each change (Full sync). It likely re-evaluates on every change and pushes updated diagnostics.

**Q: Is it a single .exe or are there DLLs/data files?**
A: **Single `.exe` file.** The zip contains only `harper-ls.exe`. No DLLs, no data files, no additional resources.

**Q: What happens if I send `shutdown` with `"params": {}`?**
A: Harper returns an error: `{"code": -32602, "message": "Unexpected params: {}"}`. Either omit `params` entirely or use `"params": null`.

**Q: What severity does Harper use?**
A: Spelling errors use `severity: 4` (Hint). We did not encounter grammar errors in this test, but they would likely use higher severity levels.

**Q: What Harper-specific execute commands are available?**
A: The server advertises 6 commands via `executeCommandProvider`:
- `HarperRecordLint` — record lint telemetry
- `HarperAddToUserDict` — add word to user dictionary
- `HarperAddToWSDict` — add word to workspace dictionary
- `HarperAddToFileDict` — add word to file-level dictionary
- `HarperOpen` — open something (not tested)
- `HarperIgnoreLint` — ignore/suppress a diagnostic
